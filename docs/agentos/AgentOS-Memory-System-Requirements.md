# LingXi 记忆系统功能需求清单

本清单明确了 AgentOS 架构下记忆系统必须具备的核心功能，摒弃冗余概念，仅保留最直接的工程要求与业务逻辑。

## 一、 记忆提取与摄入

1. **前置品味识别**：在响应包含自由描述的用户输入时，必须在执行核心任务之前，先自动嗅探并提取具有长期记忆价值的内容（如偏好、约束、局部决策）。
2. **主动记忆录入**：系统需暴露特定的强制指令（如 `/remember`），让用户能主动将一段规范或上下文送入记忆识别与保存流程。
3. **高频心跳蒸馏 (30min)**：依靠可扩展的系统级心跳机制（周期为 30 分钟），自动寻址并拉取近期未处理的历史对话流水 (Transcripts) 静默提炼经验。产出提案暂存入全局缓冲，待沙盒闲时排队落盘。

## 二、 记忆检索与应用

4. **双路并发搜索机制**：检索记忆时，必须同时使用“大模型语义相似度搜索”和“标题与正文关键词硬匹配”，合并两次结果以保证召回率。
5. **前置约束检索 (Pre-Retrieve)**：在代码或任务**执行前**，根据用户初始意图，仅检索带有“事前生效”标签的记忆（如代码规范、防坑指南），并以此约束接下来的执行行为。
6. **后置义务检索 (Post-Retrieve)**：在任务**执行结束后**，以执行结果（实际修改的文件、破坏范围）为搜寻线索，仅检索带有“事后生效”标签的滞后规定（如“改了库文件必须同步改 README”、“更新版本号”），扫出后放入任务队列继续处理。
7. **防干扰决策注入**：命中的记忆不能无脑生效，系统必须在处理日志中显式对每条召回记忆标注“采纳”、“拒绝”或“暂停询问用户”。

## 三、 记忆写入与存储

8. **跨层级实体存储**：支持将记忆明确保存到“当前项目专属目录”或“团队跨项目共享目录”两个不同的物理位置。
9. **写入前查重与防突变门控**：向库内写记忆前，强制执行 TopK 相似度检索。完全相同的静默去重；细节互补的执行合并；遇到颠覆已有定义的低置信度新规，必须拦截并向用户询问确认。

## 四、 大盘治理与维护

10. **统一注册表维护**：任何记忆增删改，都必须同步反映到一个唯一的中心索引文件（如 `INDEX.md`）中。
11. **索引自愈与清理**：提供能够一键校对的脚本或流程，清理注册表中实际已丢失文件的“死链”，并自动为未注册的实体文件补写标题和生效触发条件。
12. **全局碎片排查**：支持主动盘点整库状态，评估记忆点是否过于松散，向用户推荐归档过时记忆、合并同类项或废除冲突条款。
13. **低频心跳诊断 (24h)**：复用心跳体系触发长周期（24 小时）诊断钩子，唤起专门的代理 (`self-iterate`) 评估大盘记忆的熵增情况与沉淀质量，给出深度的重构、合并或系统迭代提案。
