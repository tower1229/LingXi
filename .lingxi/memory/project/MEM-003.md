## Context / Decision

- **Decision**: 在修改灵犀代码或配置并准备发布时，选择「按语义化版本规则更新版本号，并确保安装程序可安装最新版」；当涉及核心文件增删时，额外同步更新安装清单与架构文档，保证安装与架构描述一致。
- **Alternatives**: 仅改代码不改版本、发布前不验证安装最新版本、仅改文件不更新清单/文档（已拒绝）。
- **Counter-signals**: 纯草稿或不进入发布链路的临时实验改动，可暂不触发版本递增，但在进入发布前必须补齐。

## L0 / L1

- **L0（事实层）**: 在修改灵犀代码或配置并准备发布场景下，用户明确选择「每次修改都按语义化版本规则更新版本号，并确保安装程序可以安装最新版的灵犀」；同时延续核心文件变更需同步清单与架构文档的约束；来源为 remember。
- **L1（原则层）**: 对灵犀的每次修改都遵循语义化版本递增，并同步保障安装程序可安装最新版；涉及核心文件变更时同步维护安装清单与架构文档，确保发布链路一致可用。

## Pointers

- 版本与安装：`package.json` 版本号、安装脚本及安装清单需保持一致，发布前验证可安装最新版。
- 安装清单与架构文档：如 `install/` 下安装清单（install-manifest.json 等）、架构说明（如 about-lingxi 的 architecture 等）；核心文件变更时需同步更新上述清单与文档。
