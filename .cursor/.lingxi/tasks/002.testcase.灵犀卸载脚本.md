## 2. 集成测试用例

### TC-001: 安装后用户项目 scripts/ 下存在卸载脚本

**来源需求编号**：F1

**前置条件**：

- 使用 install 脚本（bash.sh 或 powershell.ps1）将灵犀安装到一空项目或测试目录

**测试步骤**：

1. 执行安装脚本完成安装
2. 检查用户项目根目录下是否存在 `scripts/` 目录
3. 检查是否存在 `scripts/lx-uninstall.mjs`（或 manifest 中声明的卸载脚本名）

**预期结果**：

- 存在 `scripts/` 目录
- 存在 `scripts/lx-uninstall.mjs`（或约定脚本名），且可从项目根执行 `node scripts/lx-uninstall.mjs`

**边界条件**：

- 用户项目原本无 scripts 目录：安装后应创建 scripts 并放入卸载脚本

---

### TC-002: yarn lx:uninstall / npm run lx:uninstall 可触发卸载

**来源需求编号**：F2

**前置条件**：

- 灵犀已安装到测试项目，package.json 中已注册 lx:uninstall

**测试步骤**：

1. 在项目根执行 `yarn lx:uninstall --yes`（或 `npm run lx:uninstall -- --yes`）
2. 观察脚本是否执行且退出码为 0

**预期结果**：

- 命令执行成功，无报错；.cursor/.lingxi 及清单内路径被删除（可与 TC-003/TC-004 合并验证）

---

### TC-003: 执行卸载后 .cursor/.lingxi/ 及其下全部被删除

**来源需求编号**：F3

**前置条件**：

- 灵犀已安装且已运行过 init 或存在 .cursor/.lingxi/ 目录及子内容（tasks、memory、workspace 等）

**测试步骤**：

1. 执行卸载（带 --yes 或确认后）
2. 检查 `.cursor/.lingxi/` 是否存在

**预期结果**：

- `.cursor/.lingxi/` 不存在（或其下无灵犀创建的目录与文件）

**边界条件**：

- 原本不存在 .cursor/.lingxi/：脚本应跳过不报错，退出码 0

---

### TC-004: 执行卸载后清单内 .cursor 与 scripts 路径已删除

**来源需求编号**：F4

**前置条件**：

- 灵犀已安装；install-manifest 中列出的 commands、skills、hooks、agents、references 及 scripts 在用户项目中存在

**测试步骤**：

1. 执行卸载（带 --yes）
2. 按 install-manifest 逐项检查：.cursor 下对应路径、scripts 下对应文件是否已不存在

**预期结果**：

- 清单内所列路径均已删除；scripts 下灵犀提供的 lx-* 脚本已删除

---

### TC-005: 清单外 .cursor / scripts 内容保留

**来源需求编号**：F4

**前置条件**：

- 用户项目中存在非灵犀的 .cursor 或 scripts 内容（如用户自建 .cursor/rules/ 或 scripts/my-tool.js）

**测试步骤**：

1. 执行卸载（带 --yes）
2. 检查上述用户自有路径是否仍存在

**预期结果**：

- 未列入安装清单的路径与文件未被删除

---

### TC-006: 无 --yes 时提示确认；有 --yes 时直接执行

**来源需求编号**：F6

**前置条件**：

- 灵犀已安装到测试项目

**测试步骤**：

1. 执行 `node scripts/lx-uninstall.mjs`（不传 --yes），在 TTY 环境下观察是否有确认提示或将要删除的路径列表
2. 执行 `node scripts/lx-uninstall.mjs --yes`，观察是否不经确认直接执行删除

**预期结果**：

- 无 --yes 时：有确认提示或路径列表，未确认则不删除（或退出）
- 有 --yes 时：直接执行删除
