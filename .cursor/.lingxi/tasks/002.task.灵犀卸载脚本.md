## 1. 概述

### 1.1 背景

灵犀通过安装程序将核心文件（commands、skills、agents、rules 等）与脚本（如 workspace-bootstrap）写入项目的 `.cursor/` 及 `scripts/` 目录，并通过 workspace-bootstrap 与 `/init` 在项目内创建 `.cursor/.lingxi/` 运行数据（tasks、memory/project、memory/share、workspace 日志等）。用户若不再使用灵犀或需重置工作区时，需有明确、可重复执行的卸载方式，**彻底清除**灵犀核心文件与运行文件，不留残留。

### 1.2 问题描述

当前仅有“安装/初始化”路径（远程安装脚本 + workspace-bootstrap + `/init`），没有官方卸载脚本与统一入口。用户无法通过一条明确指令一次性、彻底地删除灵犀**核心文件**（随安装写入的 .cursor 与 scripts 内容）与**运行文件**（任务、记忆库、日志等），易产生残留或误删不确定性。

### 1.3 解决方案概述

- 卸载脚本存放在**脚本仓库的 `scripts` 目录**，随安装程序一起安装到用户项目中（即安装后用户项目内存在 `scripts/` 下灵犀提供的脚本）。
- 用户通过**快捷指令 `lx:uninstall`** 执行卸载（如 `yarn lx:uninstall` 或 `npm run lx:uninstall`，由安装程序在用户项目 package.json 中注册）。
- **统一风格**：灵犀提供的所有脚本均使用 `lx:` 前缀（如 `lx:uninstall`、`lx:bootstrap` 等），与现有脚本命名对齐。
- 卸载范围：**灵犀运行文件**（.cursor/.lingxi/ 下全部：任务文件、记忆库、工作区日志、审计日志等）+ **灵犀核心文件**（随安装写入的 .cursor 下 commands、skills、agents、rules 等，以及 scripts 目录下灵犀提供的脚本），确保卸载后项目内无灵犀相关残留。
- 以安装清单（如 install-manifest 或 workflow-skeleton 扩展）为 SSoT 确定删除路径；支持安全确认（如 --yes 或交互确认）。

## 2. 目标

| 编号 | 目标 | 优先级   |
| ---- | ---- | -------- |
| G1   | 用户可通过快捷指令 `lx:uninstall` 彻底清除灵犀核心文件与运行文件（任务、记忆库、日志等），卸载后无残留 | 必须实现 |
| G2   | 卸载脚本存放在 scripts 目录，随安装程序一起安装到用户项目；卸载范围由安装清单/SSoT 确定 | 必须实现 |
| G3   | 灵犀提供的脚本统一使用 `lx:` 前缀（含卸载及现有脚本） | 必须实现 |
| G4   | 脚本可安全执行（确认或 --yes），避免误删非灵犀文件 | 应该实现 |

### 2.1 非目标

- 不提供卸载前自动备份或数据恢复能力；用户如需保留数据须自行备份后再执行卸载。

## 4. 验收检查清单

- [ ] 卸载脚本存在于 scripts 目录，并随安装程序安装到用户项目
- [ ] 用户可通过 `yarn lx:uninstall`（或 npm run lx:uninstall）执行卸载
- [ ] 执行后 `.cursor/.lingxi/` 及其下全部（任务、记忆库、工作区日志等）被删除
- [ ] 执行后灵犀核心文件（以安装清单为准：.cursor 下 commands、skills、agents 等及 scripts 下灵犀脚本）被删除，清单外内容保留；验收以清单判定无灵犀残留
- [ ] 灵犀提供的脚本在 package.json 中均使用 `lx:` 前缀
- [ ] 具备确认或 --yes 机制，文档中有卸载说明与 lx:uninstall 用法
