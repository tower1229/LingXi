# Distill Rules

Focus on:

- durable coding preferences
- recurring review tendencies
- stable engineering heuristics
- project constraints that reappear across sessions

Do not capture:

- temporary implementation chatter
- one-off shell commands
- transient debugging observations

Signal patterns that should usually be considered:

- explicit preferences
- repeated "avoid" or "do not" constraints
- stable review concerns
- explicit "must" constraints tied to project work

Each distilled item must be reusable in future task or vet work.
